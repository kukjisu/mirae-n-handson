# item-bank-php 비즈니스 규칙 후보

대상: `legacy/item-bank-php` · 선행 문서: [ARCHITECTURE.md](ARCHITECTURE.md)(진입점 · 의존 관계), [ERD.md](ERD.md)(테이블 · 읽기/쓰기 위치).
근거 파일: `search.php`, `register.php`, `units.php`, `db/mariadb/init/01-schema.sql`. 줄번호는 모두 이 파일들 기준이다.

작성 원칙

- 코드(조건문 · SQL)에 있는 것만 규칙으로 올렸다. 주석에만 있는 내용은 규칙으로 올리지 않고 비고와 [주석만 있는 내용](#주석만-있는-내용)에 모았다.
- 주석과 코드가 다르면 코드를 기준으로 규칙을 적고, 주석은 비고에 남겼다.
- 확신도: **확실** = 조건문 · SQL 로 확인. **추정** = 이름 · 주석 · DB 설정에서 짐작했고 실제 실행으로 확인하지 않음.
- **문항 "수정" 기능은 이 모듈에 없다.** UPDATE 문도, 수정 화면도 없다(ERD.md §3, `grep -niE "update"` 결과는 register.php:87 의 `FOR UPDATE` 뿐). 그래서 수정 시 검증 규칙은 뽑을 수 없었다. 등록 검증만 있다.

## A. 목록의 제외 조건 (노출 대상)

### BR-01
- 규칙: 문항의 `status` 가 `'A'` 가 아니면 검색 결과와 검색 건수에서 제외한다.
- 근거: search.php:522, search.php:525-526, 01-schema.sql:70
- 근거 코드:
  ```php
  $from   = " FROM v_item_public";
  ```
  ```sql
  WHERE i.status = 'A';
  ```
- 확신도: 확실
- 비고: 필터는 PHP 코드가 아니라 뷰 정의에 있다. `'A'` = 공개, `'D'` = 삭제, `'R'` = 검수중이라는 의미는 스키마 주석(01-schema.sql:26)에만 있다. BR-03 과 같은 규칙을 다른 방식(뷰 vs 직접 조건)으로 구현한다.

### BR-02
- 규칙: 문항이 `unit` 테이블의 단원과 조인되지 않으면 검색 결과에서 제외한다.
- 근거: 01-schema.sql:69
- 근거 코드:
  ```sql
  JOIN unit u ON u.id = i.unit_id
  ```
- 확신도: 확실
- 비고: 내부 조인이다. 다만 `fk_item_unit`(01-schema.sql:32)이 있어 정상 데이터에서는 빠지는 행이 없다. 이관 시 LEFT JOIN 으로 바꾸어도 결과가 같은지는 FK 가 보장한다.

### BR-03
- 규칙: 단원 목록의 "공개 문항 수"는 `status = 'A'` 인 문항만 센다.
- 근거: units.php:17
- 근거 코드:
  ```php
  (SELECT COUNT(*) FROM item i WHERE i.unit_id = u.id AND i.status = 'A') AS item_count
  ```
- 확신도: 확실
- 비고: 같은 "공개" 판정을 search.php 는 뷰로, units.php 는 `item` 에 직접 조건으로 건다(같은 규칙, 두 곳 구현). 공개 문항이 0개인 단원도 목록에 나온다(서브쿼리라 단원이 빠지지 않음, units.php:16-19).

## B. 문항 검색 — 조건 조합

### BR-04
- 규칙: 검색 조건(키워드 · 단원 · 난이도 · 태그)이 여럿 주어지면 모두 AND 로 결합한다.
- 근거: search.php:44, 98, 118, 215, 218, 226, 244
- 근거 코드:
  ```php
  $where    = " WHERE 1=1";
  $where .= " AND unit_code = ?";
  ```
- 확신도: 확실
- 비고: 조건 사이 OR 는 없다. OR 는 키워드 안(제목 OR 지문, BR-06)에만 있다.

### BR-05
- 규칙: 같은 이름의 GET 파라미터가 배열로 들어오면(`tag[]=a&tag[]=b` 등) 첫 값만 쓴다.
- 근거: search.php:55, 59, 63, 67, 71, 75, 79
- 근거 코드:
  ```php
  $tag = is_array($params['tag']) ? (string)reset($params['tag']) : (string)$params['tag'];
  ```
- 확신도: 확실
- 비고: 따라서 태그 · 단원 · 난이도는 **한 번에 하나씩만** 필터할 수 있다. 여러 태그 AND/OR 검색은 없다.

### BR-06
- 규칙: 키워드가 비어 있지 않으면 제목 또는 지문에 키워드가 포함된 문항만 남긴다(`%키워드%` 부분 일치).
- 근거: search.php:85, 90, 97-98
- 근거 코드:
  ```php
  $like = '%' . $q . '%';
  $where .= " AND (title LIKE ? OR stem LIKE ?)";
  ```
- 확신도: 확실
- 비고: 앞뒤 공백을 지운 뒤(search.php:85) 판단한다. 공백만 입력하면 조건 없음.

### BR-07
- 규칙: 키워드의 `%` · `_` 는 이스케이프하지 않고 LIKE 와일드카드로 그대로 쓴다(경고만 표시).
- 근거: search.php:94-97
- 근거 코드:
  ```php
  if (strpos($q, '%') !== false || strpos($q, '_') !== false) {
      $warnings[] = '키워드의 % 와 _ 는 와일드카드로 처리됩니다.';
  ```
- 확신도: 확실
- 비고: 이관 시 이스케이프를 추가하면 동작이 바뀐다(예: `q=_` 는 모든 문항과 일치).

### BR-08
- 규칙: 키워드가 100자를 넘으면 앞 100자만 써서 검색하고 경고를 낸다.
- 근거: search.php:86-88, search.php:494
- 근거 코드:
  ```php
  if (mb_strlen($q, 'UTF-8') > 100) {
      $q = mb_substr($q, 0, 100, 'UTF-8');
  ```
- 확신도: 확실
- 비고: 매직 넘버 100. 폼 입력칸에도 `maxlength="100"`(search.php:494)이 따로 박혀 있다(같은 값, 두 곳). 한 글자 키워드는 막지 않고 경고만 낸다(search.php:91-93).

### BR-09
- 규칙: 단원 코드가 비어 있지 않으면 `unit_code` 가 입력값과 같은 문항만 남긴다.
- 근거: search.php:109-110, 118-120
- 근거 코드:
  ```php
  $where .= " AND unit_code = ?";
  $values[] = $unit;
  ```
- 확신도: 확실
- 비고: 부분 일치가 아니라 `=` 비교다.

### BR-10
- 규칙: 단원 코드가 형식(`영문1자 + 숫자1~2 + '-' + 숫자1~2`)에 맞지 않거나, 소문자가 섞여 있거나, `unit` 테이블에 없어도 검색을 막지 않고 입력값 그대로 조회하며 경고만 낸다.
- 근거: search.php:111-117, 141-143
- 근거 코드:
  ```php
  if (!preg_match('/^[A-Za-z][0-9]{1,2}-[0-9]{1,2}$/', $unit)) {
      // 형식이 달라도 그대로 조회한다 (결과는 대개 0건)
  ```
- 확신도: 확실
- 비고: 대문자 변환을 하지 않는다(search.php:115-116). 그러나 `unit` · `item` 의 콜레이션이 `utf8mb4_unicode_ci`(01-schema.sql:18, 33)라 `m5-1` 도 `M5-1` 과 일치할 **가능성이 높다** — 이 경우 "대문자로 입력하세요" 경고는 뜨지만 결과는 나온다. 실행해서 확인하지 않았다(→ BR-11 도 동일).

### BR-11
- 규칙: 난이도가 비어 있으면 난이도 5 문항을 제외한다(`level < 5`).
- 근거: search.php:213-216
- 근거 코드:
  ```php
  // 난이도 값이 비어 있으면 전체 난이도 검색 (1~5 모두 포함)
  if ($level == '') {
      $where .= " AND level < 5";
  ```
- 확신도: 확실
- 비고: **주석과 코드 불일치.** 주석은 "1~5 모두 포함", 코드는 5 를 뺀다. 폼의 기본 선택지 라벨도 "전체"다(search.php:192). **아무 조건 없이 검색하는 기본 화면에서도 난이도 5 문항은 절대 안 보인다.** 이 경우 요약에는 난이도 항목이 들어가지 않아(search.php:214-216 에 `$summary[]` 없음) "조건 없이 검색했습니다"(search.php:356)로 표시된다. 이관 시 보존할지 고칠지 결정 필요.

### BR-12
- 규칙: 난이도가 `1`~`5` 한 자리 숫자이면 그 난이도와 같은 문항만 남긴다.
- 근거: search.php:217-221
- 근거 코드:
  ```php
  else if (preg_match('/^[1-5]$/', $level)) {
      $where .= " AND level = ?";
  ```
- 확신도: 확실
- 비고: `level=5` 를 명시하면 5 문항이 나온다(BR-11 과 대비).

### BR-13
- 규칙: 난이도가 비어 있지 않고 `^[1-5]$` 에 맞지 않으면 PHP `(int)` 변환값과 같은 난이도로 조회하고 경고를 낸다.
- 근거: search.php:223-229
- 근거 코드:
  ```php
  $warnings[] = '난이도는 1~5 사이여야 합니다.';
  $where .= " AND level = ?";
  $values[] = (int)$level;
  ```
- 확신도: 확실
- 비고: 주석은 "대개 0건"(search.php:224)이지만 `(int)` 변환 규칙 때문에 예외가 있다: `abc`·`0`·`6` → 0/6 → 0건, **`05`·`3abc`·`2.9` → 5/3/2 로 조회되어 결과가 나온다**(경고와 함께). 이관 시 엄격한 정수 파싱으로 바꾸면 동작이 달라진다.

### BR-14
- 규칙: 태그가 비어 있지 않으면 그 태그 이름과 정확히 같은 태그가 붙은 문항만 남긴다.
- 근거: search.php:235-236, 244-247
- 근거 코드:
  ```php
  $where .= " AND EXISTS (SELECT 1 FROM item_tag it JOIN tag t ON t.id = it.tag_id"
          . " WHERE it.item_id = v_item_public.id AND t.name = ?)";
  ```
- 확신도: 확실
- 비고: `=` 비교라 `%` · `_` 는 와일드카드가 아니다(경고만, search.php:237-239) — 키워드(BR-07)와 반대. 등록되지 않은 태그여도 조회는 그대로 해서 0건이 된다(search.php:250, 258-260). 등록 여부 판정은 PHP `===`(대소문자 구분, search.php:253)인데 SQL 비교는 콜레이션 `unicode_ci`(01-schema.sql:40)를 따른다 — 영문 태그라면 "등록되지 않은 태그" 경고가 뜨면서 결과는 나올 수 있다(추정, 미실행).

### BR-15
- 규칙: 태그 이름이 50자를 넘으면 앞 50자만 써서 검색하고 경고를 낸다.
- 근거: search.php:240-242
- 근거 코드:
  ```php
  if (mb_strlen($tag, 'UTF-8') > 50) {
      $tag = mb_substr($tag, 0, 50, 'UTF-8');
  ```
- 확신도: 확실
- 비고: 50 은 `tag.name VARCHAR(50)`(01-schema.sql:37)과 같은 값이지만 코드는 스키마를 참조하지 않는 하드코딩이다.

## C. 문항 검색 — 정렬

### BR-16
- 규칙: `sort` 가 비어 있으면 난이도 내림차순, 같은 난이도면 id 오름차순으로 정렬한다.
- 근거: search.php:317-320
- 근거 코드:
  ```php
  case '':
      // 기본 정렬: 어려운 문항부터, 같은 난이도면 번호 순
      $orderBy = " ORDER BY level DESC, id ASC";
  ```
- 확신도: 확실
- 비고: BR-11 과 겹치면, 기본 화면은 "난이도 4 부터" 시작한다(5 는 제외되므로). 주석의 "어려운 문항부터"와 실제 첫 행이 다를 수 있다.

### BR-17
- 규칙: `sort` 가 `id` · `title` · `unit` · `level` · `created` 가 아니면 기본 정렬(BR-16)을 쓰고 경고를 낸다.
- 근거: search.php:266, 322-326
- 근거 코드:
  ```php
  default:
      $warnings[] = '알 수 없는 정렬 기준입니다. 기본 정렬을 사용합니다.';
      $orderBy = " ORDER BY level DESC, id ASC";
  ```
- 확신도: 확실
- 비고: 사실상 화이트리스트다. 사용자 입력이 ORDER BY 에 직접 들어가지 않는다. `sort` · `dir` 는 소문자로 바꾸고 공백을 지운 뒤 비교한다(search.php:266-267) — `SORT=Level` 같은 입력도 받는다. 기본 정렬 문자열이 두 곳(search.php:319, 325)에 중복되어 있다.

### BR-18

- 근거: search.php:268-273

  ```php
  if ($dir !== 'asc' && $dir !== 'desc') {
      if ($dir !== '') {
  ```
- 확신도: 확실
- 비고: —

### BR-19
- 규칙: 방향이 미지정이면 `id` · `title` · `unit` 은 오름차순, `level` · `created` 는 내림차순으로 정렬한다.
- 근거: search.php:278-282, 286-290, 294-298, 302-306, 310-314, 328-331
- 근거 코드:
  ```php

  if ($dir === 'asc') {
  $dir = ($sort === 'level' || $sort === 'created') ? 'desc' : 'asc';
  ```

### BR-20
- 규칙: `id` 이외의 기준으로 정렬하면 동률을 id 오름차순으로 끊는다(정렬 방향과 무관).

### BR-21
- 규칙: 단원 정렬이면 단원 코드(지정 방향) → 난이도 내림차순 → id 오름차순으로 정렬한다.

### BR-22
- 규칙: 결과 표의 열 머리글 정렬 링크는 현재 정렬 열이면 방향을 뒤집고, 아니면 `asc` 로 — 단, 난이도 열은 첫 클릭에 `desc` 로 — 연결한다.
- 근거: search.php:399-415
- 근거 코드:

  ```php
      // 난이도는 첫 클릭에 내림차순
  ```

- 비고: 머리글 링크는 `id` · `title` · `unit` · `level` 넷뿐이다(search.php:392-397). `created` 정렬은 URL 로만 가능하고 화면에 링크가 없다. 태그 열은 정렬 불가(search.php:418).

## D. 문항 검색 — 페이지 · 결과 표시

### BR-23
- 규칙: 검색 결과는 한 페이지에 20건씩 보여 준다.
- 근거: search.php:349, 523, 553
- 근거 코드:
  ```php
  $offset = ($page - 1) * 20;
  $limit  = " LIMIT 20 OFFSET " . (int)$offset;
  'page_size'    => 20,
  ```
- 확신도: 확실
- 비고: 매직 넘버 20 이 **세 곳**에 따로 하드코딩되어 있다. 하나만 바꾸면 OFFSET · LIMIT · 페이지 수 계산(search.php:685)이 어긋난다.

### BR-24
- 규칙: 페이지 번호가 숫자만으로 되어 있지 않으면 1페이지를 보여 주고, 값이 `''`·`'1'` 이 아니면 경고를 낸다.
- 근거: search.php:77, 336-341
- 근거 코드:

## 미확인

- **문항 수정 · 삭제 · 검수 완료 규칙.** 이 모듈에 UPDATE · DELETE 가 없어 뽑지 못했다. `status` 전환, `updated_at` 갱신, `item_tag` 해제는 다른 모듈 · 운영 절차에서 확인해야 한다.
- **콜레이션에 따른 대소문자 무시 일치**(BR-10, BR-14 비고). 스키마 선언만 보고 추정했다. 실제 DB 에 붙어 `unit=m5-1` 로 요청해 보지 않았다.
- **태그 id 중복 전송 시 롤백**(BR-36 비고). 코드 경로와 PK 로 추론했고 실행하지 않았다.
- **`unit_code` 문자열 정렬 결과**(BR-21 비고). 시드(`02-seed.sql`)의 단원 코드와 대조하지 않았다.
- **PHP 7.4 의 `$level == ''` 느슨한 비교**(search.php:214). `trim` 뒤 문자열끼리 비교라 `''` 일 때만 참으로 보았다. `'0'` 은 BR-13 경로로 간다고 판단했다(실행 확인 안 함).
