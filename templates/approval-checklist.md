# 승인 체크리스트 v1 · 2회차

v1 · 2회차 (2026-10-06) — v0 에서 바뀐 점
1. 사람마다 답이 갈리는 주관 항목을 모두 예/아니오로 답할 수 있는 문장으로 바꿨다.
2. 치명 이슈 6종을 정했다. 범위 밖 변경은 파일 1개라도 있으면 반려다. 예외는 같은 파일 안의 import 정리뿐이다.
3. 컨벤션은 반려 항목(계층 위반 · 빈 catch · `System.out` · `printStackTrace()` · `console.log`)과 경고 항목(네이밍 · 포맷팅)으로 나눴다. 리뷰 기록에 비밀값을 남기지 않는 규칙을 추가했다.
4. 치명 이슈 3종 추가(총 9종). (2026-10-13)

AI 가 만든 변경분 · 외주사 PR 을 머지하기 전에 리뷰어가 대조하는 목록이다. 1~4 의 네 기준이 **모두** 충족되어야 승인이다. 하나라도 미충족이면 반려다. 5 는 리뷰어가 쓰는 기록에 대한 항목이다.

모든 항목은 "예"가 충족이다. 하나라도 "아니오"이면 그 기준은 미충족이다. 단, **경고**로 표시한 항목은 기준 판정에 넣지 않고 이슈 목록에만 올린다.

## 심각도 정의

- **치명** — 2번 기준의 항목에 해당하는 문제. 1건이라도 있으면 반려.
- **경고** — 지금 고치지 않아도 동작하지만 다음 변경에서 사고가 될 가능성이 있는 문제. 경고만으로는 반려하지 않는다.
- **제안** — 더 나은 방법이 있다는 의견. 승인 · 반려에 영향을 주지 않는다. 목록으로만 남긴다.

이슈 한 건은 심각도 · `파일:줄번호` · 근거 · 수정 방향 네 항목으로 적는다. 근거 줄번호를 댈 수 없는 지적은 "확인 필요"로 따로 둔다.

## 1. 테스트 통과

- [ ] 변경된 모듈의 테스트 명령을 실제로 실행했는가? (실행하지 않았으면 통과로 쓰지 않는다.)
- [ ] 실행 결과에 실패 · 오류가 0건인가?
- [ ] 새로 추가된 Controller · Service 의 public 메서드마다, 같은 패키지의 `src/test/java` 에 그 메서드를 호출하는 테스트가 있는가? (getter · setter · 생성자 같은 접근자는 제외한다.)
- [ ] 기존 테스트를 지우거나 건너뛰게(`skip`, `@Disabled`) 바꾼 곳이 0곳인가? (1곳이라도 있으면 반려한다.)

## 2. 치명 이슈 0건

- [ ] 비밀번호 · 토큰 · 키가 코드 · 설정 · 테스트 픽스처 · 리뷰 기록에 리터럴로 들어간 곳이 0곳인가?
- [ ] 요청 문장에 없는 데이터 삭제 · 덮어쓰기 코드가 0곳인가?
- [ ] SQL 을 문자열로 이어 붙여 만드는 곳이 0곳인가? (파라미터 바인딩만 쓰는가?)
- [ ] 인증 · 권한 검사를 우회하거나 끄거나 건너뛰게 바꾼 곳이 0곳인가?
- [ ] `legacy/` 아래 변경 파일이 0개인가?
- [ ] `characterization/` 의 기존 테스트 · 스냅샷(`__snapshots__/`) 변경이 0건인가?
- [ ] 로그 · 응답 · 오류 메시지에 학생 식별자(`STU-<숫자>`) · 이메일 · 토큰을 원문으로 남기는 곳이 0곳인가?
- [ ] 외부 입력(요청 파라미터 · 본문 · 헤더)을 새로 받는 곳마다 서버에서 타입 · 범위 · 길이 · 허용 목록 중 해당하는 검증을 하는가?
- [ ] Terraform IAM 정책에 `Action = "*"` 또는 `Resource = "*"` 가 들어간 곳이 0곳인가?

## 3. 요청 범위 이탈 없음

- [ ] 요청 문장을 한 문장으로 확인했는가? (확인하지 못했으면 판정하지 않고 먼저 묻는다.)
- [ ] 요청 문장으로 설명되지 않는 변경 파일이 0개인가? (1개라도 있으면 반려한다.)
- [ ] 요청 문장으로 설명되는 파일 안에서, 요청과 무관한 변경이 import 정리 말고는 없는가?
- [ ] 의존성 추가(`build.gradle` · `package.json`) · DB 스키마 변경(`db/`) · 설정 파일 변경이 있다면, 그 내용이 요청 문장에 들어 있는가?

## 4. 컨벤션 준수

- [ ] 팀 `CLAUDE.md` 의 코딩 컨벤션과 금지 사항을 대조했는가? (`convention-check` Skill 이 있으면 그 결과를 쓴다.)
- [ ] 컨트롤러가 Repository 를 주입받거나 SQL 문자열 · JdbcTemplate · EntityManager 를 직접 쓰는 곳이 0곳인가?
- [ ] 아무 처리 없이 비워 둔 catch 블록이 0곳인가?
- [ ] `System.out` · `printStackTrace()` · `console.log` 가 0곳인가?
- [ ] (경고) 새 클래스 · 메서드 · 변수 이름이 주변 코드의 네이밍 규칙과 같은가?
- [ ] (경고) 들여쓰기 · 줄바꿈 등 포맷팅이 주변 코드와 같은가?

## 5. 리뷰 기록

- [ ] 리뷰 리포트와 판정표에 비밀값 원문이 0건인가? (위치는 `파일:줄번호` 로 적고 값은 `****` 로 가린다.)

## 판정 형식

첫 줄에 `판정: 승인` 또는 `판정: 반려`를 쓴다. 이어서 네 기준의 충족 · 미충족 표를 쓰고, 그다음 이슈 목록(심각도 · `파일:줄번호` · 근거 · 수정 방향)을 쓴다. 코드는 수정하지 않는다.
