# 레거시 모듈 문서화

## 원칙
- 분석 대상 폴더(`$ARGUMENTS` 의 모듈 경로)의 파일은 **읽기만 한다.** 수정 · 이동 · 포맷팅하지 않는다.
- 쓰는 파일은 `docs/<모듈명>/` 아래 3개뿐이다: `ARCHITECTURE.md`, `ERD.md`, `BUSINESS-RULES.md`.
- `<모듈명>` 은 폴더 이름이 아니다: `legacy/item-bank-php` → `item-bank`, `legacy/assignment-thymeleaf` → `assignment`, `legacy/grade-mssql` → `grade`.
- 범위 제한 인자가 있으면 그 파일 · 기능만 분석하고, 각 문서 머리에 범위를 적는다.
- 단계가 끝날 때마다 결과를 파일로 저장한 뒤 다음 단계로 넘어간다. 저장 전에는 다음 단계를 시작하지 않는다.

## 0. 계획 먼저 제시
- 파일 목록(`vendor/` · 빌드 산출물 제외)과 읽을 순서, 단계별 산출물을 짧게 보여 주고 시작한다.
- 스키마가 필요하면 `db/mariadb/init/` · `db/mssql/init/` 을 함께 읽는다(역시 읽기만).

## 1. 진입점 → `ARCHITECTURE.md`
- 요청을 받는 파일 · 메서드(PHP 페이지, `@Controller` 매핑, 저장 프로시저 호출부)를 표로: 경로 · 메서드 · 역할 · 근거 `파일:줄번호`.

## 2. 의존 관계 → `ARCHITECTURE.md` 에 추가
- 포함(require · import · 주입)과 호출(함수 · 프로시저)을 나눠 적는다. 호출 방향은 "A → B (A 가 B 를 부른다)" 로 쓰고 호출하는 줄을 근거로 단다.
- 확인 못 한 것은 `## 미확인` 에 모은다.

## 3. 데이터 흐름 → `ERD.md`
- 테이블 · 뷰 목록, 관계(FK · 조인 조건, Mermaid `erDiagram` 가능), 테이블별 읽기 · 쓰기 위치(`파일:줄번호` 와 SQL 종류), 요청 → 테이블 흐름 요약.

## 4. 비즈니스 규칙 후보 → `BUSINESS-RULES.md`
- 조건문 · SQL 에 있는 것만 규칙으로 올린다. 주석에만 있는 내용은 별도 절 "주석만 있는 내용"으로 뺀다.
- 주석과 코드가 다르면 코드를 기준으로 규칙을 쓰고, 주석은 비고에 남긴다.
- 주제별로 묶고(제외 조건 · 검색 조합 · 정렬 · 검증 · 저장 등) 아래 형식을 그대로 쓴다.

```markdown
### BR-01
- 규칙: (한 문장. 입력 → 결과로)
- 근거: search.php:522, 01-schema.sql:70
- 근거 코드:
  ```php
  (해당 줄을 그대로 복사. 요약 · 재작성 금지)
  ```
- 확신도: 확실 | 추정
- 비고: (주석과의 차이, 같은 규칙의 다른 구현 위치, 부수 효과 등)
```
- 확신도: **확실** = 조건문 · SQL 로 확인. **추정** = 이름 · 주석 · 설정에서 짐작했고 실행으로 확인하지 않음.

## 5. 사람이 표본 점검할 규칙 3개 추천
- `BUSINESS-RULES.md` 끝에 `## 표본 점검 추천` 을 두고 3개를 고른다:
  1. **가장 그럴듯한 규칙** — 읽기엔 당연해 보여서 아무도 확인하지 않을 규칙.
  2. 언어의 형 변환 · 기본값 · NULL 처리에 기대는 규칙.
  3. 부수 효과(경고 · 메시지 · 로그)가 붙은 규칙.
- 각각 확인 방법(열어 볼 `파일:줄번호`, 또는 서비스를 띄워 보낼 요청 예)을 한 줄로 적는다.
- 점검 결과를 받으면 `## 검증 이력` 표(날짜 · 방법 · 대상 · 판정 · 근거 · 문서 변경)에 기록한다.

## 하지 말 것 (item-bank 검증 이력에서 실제로 틀린 유형)
- **형 변환 결과를 짐작으로 쓰지 않는다.** 교차 검증 문서는 PHP `(int)` 가 "숫자가 아닌 문자열은 0" 이라고 적었지만, 실제로는 `(int)"3abc"=3`, `(int)"05"=5`, `(int)"2.9"=2` 였다(search.php:223-229). 캐스팅 · 암묵 변환이 결과를 가르면 확신도를 "추정"으로 두거나, 컨테이너에서 실행해 확인한 값만 적는다.
- **분기 안의 부수 효과를 빼먹지 않는다.** 교차 검증 문서는 `dir` 값이 틀렸을 때 기본값으로 돌아간다는 것만 적고 경고 메시지 추가(search.php:268-273 `$warnings[] = ...`)를 빠뜨렸다. 분기 하나를 규칙으로 옮길 때는 그 블록의 모든 문장(대입 · 경고 · 로그 · 조기 반환)을 확인한다.
- 존재하지 않는 함수 · 파일 · 테이블을 쓰지 않는다. 이름을 적기 전에 grep 으로 정의 위치를 찾고, 못 찾으면 "미확인"에 둔다.
- 호출 방향을 뒤집지 않는다. "A 가 B 를 부른다"는 A 안의 호출 줄로만 증명한다.
- 코드에 없는 규칙을 만들지 않는다. "보통 이렇다", 주석, 변수 이름만으로 규칙을 세우지 않는다.
- 줄번호를 기억으로 적지 않는다. 인용한 코드가 그 줄에 실제로 있는지 다시 읽어 맞춘다.
