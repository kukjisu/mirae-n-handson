# 장애 로그 RCA

대상: incident-logs/$ARGUMENTS/
결과: docs/rca/$ARGUMENTS.md

인자가 비어 있으면 `incident-logs/` 의 폴더 목록을 보여 주고 어느 시나리오인지 먼저 묻는다.

## 절차

1. **수집 범위**
   - 파일을 통째로 읽지 않는다. `wc`, `head`, `tail`, `grep -c`, `grep -n`, `awk` 로 파일별 줄 수 · 기록 기간 · 시각 형식 · 타임존을 먼저 표로 만든다.
   - 타임존이 다르면 KST 변환 규칙을 적는다.
   - 오류 · 경고 · 5xx · 타임아웃을 분 단위로 세어 평소 수준(기준선)과 비교하고, 이상 구간의 시작 · 끝과 앞뒤 여유(앞쪽을 더 넉넉히)를 정한다. 끝을 관측하지 못했으면 그렇다고 적는다.
2. **타임라인**
   - 구간 안의 사건을 KST 한 시간축으로 합친다. 한 줄 형식: 시각 | 출처(파일:줄번호) | 사건 요약 | 원문 발췌(80자 이내).
   - 모든 줄에 `파일:줄번호` 를 단다. 반복 메시지는 "첫 발생, 이후 N건/분"으로 묶는다.
   - 출처가 다른 두 사건의 차이가 5초 이내면 (선후 불확실) 로 표시한다.
   - 가장 많은 오류보다 앞선 징후(느린 쿼리, 경고, 설정 재적재, 배포, 트래픽 변화)를 따로 점검한다.
3. **가설**
   - 서로 다른 계층(코드 / DB · 데이터 / 배포 · 설정 / 트래픽 · 인프라)에서 2개 이상 세운다.
   - 가설마다 지지 근거(파일:줄번호), 반증 조건("이것이 확인되면 틀렸다"), 확인 방법(명령 또는 파일)을 적는다.
   - 가장 많이 나온 오류 메시지는 원인이 아니라 증상으로 다룬다.
4. **검증 · 판정**
   - 로그로 확인할 수 있는 반증을 실제로 실행하고, 명령과 결과 숫자를 그대로 남긴다. 가설마다 유지 / 기각 / 판단 불가(로그 부족)를 적고, 판단 불가면 필요한 자료를 적는다.
   - 남은 가설은 로그에 찍힌 클래스 · 메서드 · 설정 키에서 출발해 코드 · 설정(배포 변경 항목 포함)과 대조한다. 설정값은 파일에서 읽은 값만 쓴다.
   - 채택 가설 하나, 기각 사유, 확신 수준(높음 / 중간 / 낮음)과 그 이유를 적는다.
5. **리포트** — 요약(5줄 이내), 원인(직접 원인과 배경 원인 구분), 근거 로그 줄, 수정안, 재발 방지, 모니터링 항목(이번 로그에 적용했다면 경보가 울렸을 시각 포함), 확인하지 못한 것. 수정안 · 재발 방지 · 모니터링은 섞지 않는다. 코드는 고치지 않고 제안만 쓴다.
6. **마스킹** — 리포트를 저장하기 전에 이 Skill 폴더의 `masking-rules.md` 규칙을 적용하고, 리포트 맨 아래에 "마스킹 적용: 유형별 건수"를 한 줄로 남긴다.

## 하지 말 것

- 로그에 없는 줄을 인용하지 않는다. 근거가 없으면 "로그로 확인 불가"라고 쓴다.
- 가장 많이 나온 오류를 곧바로 원인이라고 부르지 않는다.
- 원본 로그와 소스 코드를 수정하지 않는다.
- 마스킹 대응표를 파일로 남기지 않는다.
- 마스킹 전 원본을 임시 폴더에 복사해 두지 않는다.
